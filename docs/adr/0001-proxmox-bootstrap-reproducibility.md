# ADR-0001: Proxmox 수동 기준 설치 후 자동설치 PoC

- 상태: `Accepted`
- 날짜: 2026-07-30
- 관련 작업: `PVE-01`, `AUTO-01`, `OS-01`

## 배경

유일한 물리 컴퓨트 노드의 설치는 기존 NVMe를 지우며, 실패하면 이후 모든 작업과 원격 복구 경로가 멈춘다. 반면 수동 설치만 유지하면 재설치 입력과 결과가 사람의 기억에 남아 재현성이 없다.

## 결정

Day 1은 독립 콘솔에서 대상 디스크, 부팅 매체와 관리 네트워크를 사람이 재확인한 뒤 Proxmox를 수동 설치한다. 설치 선택과 설치 후 검증 결과는 runbook에 기록하되 주소는 `ip-plan.md`를 참조한다.

수동 기준선이 검증된 뒤 공식 answer file 템플릿과 ISO 준비 절차를 구현한다. 버전 관리 대상은 원본 ISO의 버전·checksum, 비밀 없는 템플릿, 생성·검증 절차다. 실제 비밀이 주입된 answer file과 생성 ISO는 커밋하지 않는다. 무인 설치는 폐기 가능한 VM과 가상 디스크에서 먼저 검증하고 현재 물리 노드에는 재실행하지 않는다.

Proxmox 이후 VM은 OpenTofu, VM OS와 k3s bootstrap은 Ansible, Kubernetes 애플리케이션은 Argo CD가 소유한다.

## 검토한 대안

- **수동 설치만 유지:** 첫 설치 위험은 낮지만 재설치 절차와 입력이 검증되지 않는다.
- **첫 설치부터 무인화:** 가장 빠른 자동화처럼 보이지만 검증되지 않은 디스크 선택이 유일한 노드를 파괴할 수 있다.
- **기존 Linux에 Proxmox 패키지 설치:** 기존 상태의 영향이 남아 공식 ISO 기준선과 복구 절차가 불명확해진다.

## 결과

- Day 1 설치에는 사람의 최종 승인과 수동 절차가 남는다.
- 재현성은 생성 ISO의 바이트 동일성이 아니라 고정된 입력, 생성 절차와 깨끗한 환경의 기능 검증으로 정의한다.
- 자동설치 PoC 성공은 현재 물리 노드에 대한 재설치 승인이 아니다.

## 재검토 조건

- 동일 사양의 폐기 가능한 테스트 장비를 확보한다.
- 두 번째 물리 노드를 확보해 한 노드를 잃어도 관리 서비스를 유지할 수 있다.
- 공식 설치 도구의 answer schema나 지원 방식이 변경된다.
