# OPNsense 물리 인터페이스 재할당

검증일: 2026-07-28. 현재 배치는 `docs/ip-plan.md`가 소유한다. 이 절차는 다시 물리 포트를 옮길 때만 사용한다.

## 목적

논리 인터페이스를 다른 NIC로 옮기되 IP, DHCP, 방화벽과 VLAN 정책은 바꾸지 않는다.

## 전제와 영향

- `OPNSENSE-LIVE` 잠금을 단독으로 소유한다.
- 현장 작업자가 케이블을 즉시 옮길 수 있다.
- PiKVM/콘솔 또는 기존 포트로 되돌릴 독립 경로가 있다.
- 원본 설정을 저장소 밖에 `0600`으로 보관한다.
- 케이블 분리 시 `ifconfig`의 carrier 변화를 확인해 물리 포트를 식별한다.

적용 순간 주소·라우트·필터가 새 NIC로 재구성된다. 케이블을 옮기기 전까지 해당 네트워크와 원격 세션이 끊기는 것은 예상 영향이다.

## 실행

1. `docs/ip-plan.md`에 목표와 영향 작업을 먼저 확정한다.
2. UI 또는 승인된 Assignment API로 필요한 할당을 모두 stage한다.
3. pending 값에 IP·DHCP·VLAN 변경이 섞이지 않았는지 확인한다.
4. reconfigure/apply를 한 번만 실행한다.
5. 케이블을 목표 포트로 옮긴다.
6. 링크부터 DNS·HTTPS 순서로 검증한다.
7. 라이브 검증 후에만 드리프트 스냅샷을 갱신한다.

## 성공 판정

- 논리 인터페이스와 NIC가 `docs/ip-plan.md`와 일치한다.
- 목표 NIC는 carrier가 있고 이전 NIC는 예상 상태다.
- 직접 연결 route와 PF rule이 새 NIC에 생성된다.
- DHCP/DNS, 인터넷, 원격 접근과 HTTPS 인증서가 정상이다.
- 재부팅 후에도 유지된다.
- `infra/opnsense/scripts/check-drift.sh --update` 후 일반 실행이 드리프트 없음이다.

## 중단과 복구

검증값이 하나라도 예상과 다르면 추가 변경을 멈춘다.

1. 콘솔 `Assign interfaces`에서 직전 정상 할당으로 되돌린다.
2. 케이블도 직전 포트로 되돌린다.
3. GUI 주소가 사라졌으면 콘솔 `Set interface IP address`로 관리 접근만 복구한다.
4. 그래도 실패하면 작업 전 원본 설정을 복원한다.

원본 설정에는 비밀번호 해시, API 토큰과 인증서 개인키가 있다. 출력·공유·커밋하지 않으며 Git에는 정규화한 스냅샷만 둔다.
