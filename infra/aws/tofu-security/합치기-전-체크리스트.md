# platform-main에 합치기 전 체크리스트

project-f는 project-c의 AWS 보안 통제를 platform-main의 실제 계정(465137780685)
구조에 맞게 옮긴 코드입니다. 코드만 준비된 상태이고, 아래 항목들은 실제로
합치기 전에 온프레미스팀과 확인·처리해야 합니다.

## 1. 라이브 인프라 변경이 필요한 것 (project-f 밖, 별도 root)

- **`tofu-app-db`: `iam_database_authentication_enabled = true` 켜기**
  확인 시점 기준 꺼져 있습니다. 05(RDS PII 마스킹)/09(DB 권한 드리프트 자동
  복구) 시나리오 둘 다 IAM DB 인증 토큰으로 접속하는 걸 전제로 하는데,
  꺼져 있으면 아예 접속 자체가 안 됩니다. 라이브 프로덕션 Aurora 클러스터를
  건드리는 변경이라 project-f에서 직접 안 했습니다.
- **(선택, 정밀도 개선) `tofu-app-db`에 `aurora_cluster_resource_id` 출력 추가**
  없어서 `43-demo-scenario-resources.tf`/`30-rds-permission-drift-check.tf`의
  `rds-db:connect` IAM 권한을 정확한 클러스터 리소스 ID로 못 좁히고
  `dbuser:*/<사용자명>`으로 넓게 허용했습니다. 이 출력이 생기면 더 좁힐 수 있습니다.
- **(권장) RDS/ALB 삭제 보호 켜기**
  평소 운영에는 영향 없고 삭제 API 호출 전에 보호 해제 단계가 하나 추가될 뿐입니다.
  RDS는 `tofu-app-db`(`aws_rds_cluster.main`의 `deletion_protection`), ALB는
  `gitops/apps/hr-system/ingress.yaml`(AWS Load Balancer Controller 애노테이션)
  쪽에서 각각 설정 - 둘 다 project-f 밖입니다.

## 2. 수동으로 값을 채워야 하는 것 (apply 후, 콘솔/CLI)

| 대상 | 위치 | 비고 |
|---|---|---|
| Slack Bot Token / Signing Secret | `aws_secretsmanager_secret.slack_app` | 28번 tf |
| Keycloak admin 계정 | `aws_secretsmanager_secret.keycloak_admin` | 35번 tf. Vault에 이미 있다면 동기화 방식을 따로 정할 것 |
| `onprem_cidr_block` / `onprem_customer_gateway_ip` / `onprem_keycloak_host` | terraform.tfvars | 실제 값은 이미 알고 있음(`10.10.0.0/16`, OPNsense WAN IP, 온프레미스 Keycloak 주소) |
| `grafana_admin_role_values` / `grafana_editor_role_values` | terraform.tfvars | Grafana 전용 Keycloak SAML 클라이언트가 실제로 등록하는 그룹명과 정확히 일치해야 함 |
| `grafana_provisioning_user` | terraform.tfvars | Grafana Admin 권한 매핑된 실제 Keycloak 계정 |
| `security_auditor_allowed_cidrs`, `security_contact_name/phone`, `alert_email` 등 | terraform.tfvars | project-c의 실제 값 재사용 가능(개인정보라 여기 안 옮김) |

## 3. 수동 실행이 필요한 스크립트 (SSM 자동화 불가 - Keycloak이 온프레미스라)

- `scripts/keycloak-grafana-saml-client.sh` - 온프레미스 Keycloak 호스트에서 직접
  (`KCADM_ADMIN_USER`/`KCADM_ADMIN_PASSWORD`/`REALM_NAME` 환경변수 필요)
- `hr-data-masking-views.sql` - Aurora에 마스터 계정으로 직접 (05/09 시나리오 전제조건)

## 4. 시나리오 스크립트 실행 시 환경변수로 넘겨야 하는 값 (하드코딩 안 함)

  테스트 계정**. 실제 사람 계정을 넣으면 그 사람 세션이 진짜로 강제 종료됨.
- `13-grafana-soc-dashboard.sh`: `GRAFANA_PROVISIONING_PASSWORD`

## 5. 검증 안 된 가정 (제가 이 저장소 밖의 정보라 직접 확인 못 한 것)

- `employees`/`change_history` 테이블 스키마가 project-c와 동일하다고 가정
  (hr-app 코드베이스가 같아서 그럴 가능성이 높지만, 실제 마이그레이션 코드는
  컨테이너 이미지 안에 있어 이 저장소에서 확인 불가)
- Aurora에 pgAudit이 켜져서 "AUDIT:"로 시작하는 로그를 실제로 남기고 있는지
  (06번 시나리오의 WORM 파이프라인이 비어있을 수 있음)
